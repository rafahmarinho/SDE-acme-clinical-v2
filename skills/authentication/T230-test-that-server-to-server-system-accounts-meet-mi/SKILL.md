# T230: Test that server-to-server system accounts meet minimum password requirements

**Category:** CODE_FIX
**SD Elements:** [T230](https://sde-ent-echo.sdelab.net/bunits/afrika-sc-labs/acme-clinical-v2/acme-clinical-v2/tasks/phase/testing/32-T230/)
**Priority:** 8/10 · **Phase:** testing

**Spec Context:**
> "Entregue o código completo, configuração do banco, dados iniciais, exemplos de variáveis de ambiente e um README com os passos para rodar e publicar a versão web e a API na Vercel."
> (EN: Deliver the complete code, database configuration, initial data, environment variable examples and a README with the steps to run and publish the web version and the API on Vercel.)
> Source: specs/PRD.md, lines 45-49

**What the spec implies (naive approach):**
The `.env.example` files might ship values like `INTERNAL_API_SECRET=changeme` or `DB_PASSWORD=postgres`, and the backend would start with them. A deployment that copies the example file then runs with guessable system credentials.

**Secure Implementation Pattern:**
```python
# backend/app/core/config.py
from pydantic import SecretStr, field_validator
from pydantic_settings import BaseSettings

WEAK = {"changeme", "secret", "password", "postgres", "example", "your-secret-here", "test"}

class Settings(BaseSettings):
    supabase_url: str
    supabase_service_role_key: SecretStr       # server-only, never VITE_*
    supabase_jwt_issuer: str
    database_url: SecretStr
    internal_cron_secret: SecretStr            # Vercel Cron -> /internal/simulation/tick

    @field_validator("internal_cron_secret")
    @classmethod
    def strong_secret(cls, v: SecretStr) -> SecretStr:
        s = v.get_secret_value()
        if len(s) < 32 or s.lower() in WEAK or len(set(s)) < 10:
            raise ValueError("INTERNAL_CRON_SECRET must be >=32 random chars (e.g. `openssl rand -hex 32`)")
        return v

    @field_validator("database_url")
    @classmethod
    def strong_db_password(cls, v: SecretStr) -> SecretStr:
        from urllib.parse import urlsplit
        pw = urlsplit(v.get_secret_value()).password or ""
        if len(pw) < 16 or pw.lower() in WEAK:
            raise ValueError("Database password does not meet minimum requirements")
        return v
```
```python
# backend/tests/test_system_secrets.py
import pytest
from pydantic import ValidationError
from app.core.config import Settings

@pytest.mark.parametrize("secret", ["changeme", "short", "a" * 40])
def test_weak_system_secret_rejected(secret, base_env):
    with pytest.raises(ValidationError):
        Settings(**{**base_env, "internal_cron_secret": secret})
```

**Implementation Guidance:**
- Inventory the system credentials: the Supabase service role key (generated by Supabase and rotated in the dashboard), the Postgres connection password used by `backend/app/db.py`, and the shared secret for Vercel Cron and internal simulation calls (T10).
- Validate them at startup in `backend/app/core/config.py`. A Vercel deployment with weak values then fails fast instead of serving traffic.
- Keep `.env.example` values as obvious placeholders that fail validation (`INTERNAL_CRON_SECRET=` empty), and document `openssl rand -hex 32` in the README.
- Do not create the test account by changing a production credential. Run the tests with constructed settings only.
- Reference: SD Elements guidance for T230.

**Success Criteria:**
- [ ] `Settings()` raises for placeholder, short or low-entropy system secrets and database passwords (pytest).
- [ ] `.env.example` values do not pass validation, and the README explains how to generate real secrets.
