# T50: Use indirect object reference maps if accessing files

**Category:** CODE_FIX
**SD Elements:** [T50](https://sde-ent-echo.sdelab.net/bunits/afrika-sc-labs/acme-clinical-v2/acme-clinical-v2/tasks/phase/requirements/32-T50/)
**Priority:** 8/10 · **Phase:** requirements

**Spec Context:**
> "Use versões atuais e estáveis das tecnologias e Supabase para PostgreSQL, login por e-mail e"
> "senha, arquivos e atualizações em tempo real. Quero as telas funcionando e os dados"
> (EN: Use current, stable versions of the technologies and Supabase for PostgreSQL, email and password login, files and real-time updates. I want the screens working and the data)
> Source: specs/PRD.md, lines 5-7

**What the spec implies (naive approach):**
With Supabase Storage, the quickest download is `GET /files/download?path=patients/<id>/scan.pdf` or a frontend call to `storage.from("clinical-files").download(path)` using the path the client already knows. Changing the path (or adding `../`) reaches other patients' files, and predictable names make enumeration trivial. Report exports written to a temp file named after a parameter have the same issue.

**Secure Implementation Pattern:**
```python
# backend/app/routers/files.py
@router.get("/{attachment_id}/url", response_model=SignedUrlOut)
async def signed_url(attachment_id: UUID, principal: Principal = Depends(require(Perm.patients_read))):
    async with transaction(principal, read_only=True) as conn:
        row = await fetch_one(conn,
            "select storage_path from public.attachments a "
            "where a.id = %s and public.can_access_patient(a.patient_id) and a.deleted_at is null",
            (attachment_id,))
    row = ensure_visible(row, "Attachment")
    path = safe_object_path(row["storage_path"])      # regex: patients/<uuid>/<uuid>.<ext>, no traversal
    url = await storage.create_signed_url(BUCKET, path, expires_in=60)   # short-lived, server-side
    return SignedUrlOut(url=url, expires_in=60)

# backend/app/services/files.py - the stored path is generated, never user-chosen
def new_object_path(patient_id: UUID, ext: str) -> str:
    return f"patients/{patient_id}/{uuid4()}.{ext}"   # ext from content sniffing allowlist
```

**Implementation Guidance:**
- Clients reference files only by `attachments.id` (UUID v4) in `backend/app/routers/files.py`; the `storage_path` column is never accepted from requests and should not be returned in `AttachmentOut` (`backend/app/schemas/__init__.py`).
- Object paths are generated by `new_object_path` and validated by `safe_object_path`/`OBJECT_PATH` in `backend/app/services/files.py`; original filenames are display metadata only (`display_name`).
- Issue short-lived signed URLs after the object-level check (T378); keep the `clinical-files` bucket private and deny direct `authenticated` access in Storage RLS (`supabase/migrations/0007_privacy.sql` / `0002_roles_rls.sql`).
- Report exports in `backend/app/services/reports.py` use server-generated names in a private temp directory (`private_workdir`, `create_exclusive`), selected via `ReportKind`, not by client filename.
- Reference: SD Elements guidance for T50.

**Success Criteria:**
- [ ] No route parameter or body field named `path`, `file`, `filename` or `storage_path` is used to locate an object.
- [ ] Pytest (`backend/tests/test_files.py`): `safe_object_path("patients/../secrets")` and non-UUID paths raise; signed URL for another ward's attachment -> 404.
- [ ] Storage policy test: an `authenticated` client cannot `download` from `clinical-files` directly.
